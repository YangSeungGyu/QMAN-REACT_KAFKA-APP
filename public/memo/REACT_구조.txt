==============[기본설정파일]==============
eslint.config.js : 문법,코드 스타일
index.html : 소스가 적용될 메인html
jsconfig.json : 에디트에서 javascript설정
package.json : (**):프로젝트 정보,라이브러리 목록 관리
package-lock.json : 라이브러리 버전,의존성 고정
vite.config.js : (*)경로에대한 별칭관리, proxy설정, 포트 등

src/main.jsx : index.html과 App.jsx이 연결됨 (StrictMode를 제거하면 두번씩 실행 안함)
src/App.jsx : 최상단 리엑트 위치(각종 셋팅)



==============[React 개념]==============
 - 라우터로 각 파일을 url경로로 매칭
 - 리엑트 컴포넌트 파일은 function [컴포넌트명](){[자바스크립트] return([html소스])} 구조
 - 컴포넌트에서 액션이 일어나거나면 해당 function 단독으로 실행되는게 아니라 컴포넌트 function이 통으로 실행됨.
 - id기준으로 매핑되는게 아닌 useState에 선언된 변수로 매핑됨.
 - useState,useEffect에서 제어하는값의 변화가 있어야 실행됨.
 - 개발자모드에서는 함수가 2번씩 실행됨(StrictMode)
 
 - Atom : 버튼이나 자주쓰는형태의 ui들을 style 및 공통함수를 적용해 컴포넌트로 만들어 활용
 - Outlet : 중첩화면일때 라우터로 관리( 공통 > 서브공통 : 컨테이너 이러면 outlet2개?)

 - javascript+html 활용처럼 id나 name등 속성으로 객체를 가져오는 개념이 아님. return에 html이 있기에
   jscript가 모두 실행된 후 dom에 완성된 html이 씌워지는 개념이라 script문때는 해당 elements들이 화면에 없다고 봐야함.
 ==============[React 렌더링 동작]==============
1)랜더링 : 컴포넌트 함수를 실행시키고 설계를 우선 한다.(실행x)
2)마운트 : 설계된걸 DOM화면에 붙인다.
3)스크립트 실행
[개발환경 StrictMode 일때 추가 진행]

6)마운트 2회차 : 반복
7)스크립트 실행

==============[npm 명령어]==============
npm run dev : 실행

npm run build  : dist 폴더 생기고 여기 내용을 웹서버나 springboot에 넣으면됨
npm run preview : 서버반영전 최종확인(빌드완료된 버전으로 소스 수정해도 반영되지 않음 - build 후 사용가능)

npm install : 라이브러리 설치
npm uninstall

npm update : 패키지들 최근버전으로 변경

npm cache clean --force : npm캐쉬 청소

* package.json 에서 변경가능



==============[React 주요 모듈]==============
import { useState, useEffect, useRef } from "react";
 - useState : 화면렌더링에 관여하는 변수
 - useEffect : 화면렌더링에 관여할 함수형태
 - useRef : 렌더링에는 관여하지 않지만 기능적으로 동작할 변수(포커스 등)


import { Outlet, useOutletContext, useLocation, useNavigate, Link, useParams } from 'react-router-dom';
 - Outlet : 컴포넌트가 동적으로 변동하는곳에 선언 context를 추가할 수 있다.
 - useOutletContext : outlet에 추가한 context 활용 
 - useLocation :  {pathname:도메인 제외 경로,search:url의 파라미터,state:link나 navigate로 보낸 보이지않는값}
 - useNavigate : 소스에서 url 변경
 - Link : a태그
 - useParams : 라우터에서 /:param변수로 설정된값 가져오기
