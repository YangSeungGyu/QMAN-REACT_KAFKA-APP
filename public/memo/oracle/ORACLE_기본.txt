================[색인 및 제약조건]================
-----------INDEX-----------
특정 컬럼 및 컬럼묶음의 데이터를 따로 KEY값과 데이터가 존재하는 위치를 처음 조회될때 메모리에 올려둠.
WHERE 조건절에서 해당 값이 사용되었을때 실제 데이터 위치를 빠르게 검색함.

[참고]
- INDEX 두개를 등록했고 둘다 WHERE절에서 사용되었다면 오라클 옵티마이저 판단으로 하나만 사용함.
  여러 컬럼 묶음을 INDEX로 사용하고자 한다면 INDEX 하나에 여러컬럼을 묶어서 등록.

- INDEX를 등록한 컬럼을 함수로 변형하면 INDEX를 사용하지 않음.
   EX)   SUBSTR(EMP_NO,1,3) = '1000'  EMP_NO로 INDEX를 등록했어도 메모리에서 찾지 않음.
- 대상 구분자가 얼마 없을때는 INDEX가 되려 느림 (1억개 데이터중 2~3개의 구분자만 있는 경우 비효율)
- INDEX로 등록한 컬럼이 많을수록 INSERT,UPDATE 속도는 느려짐

-----------PK-----------
INDEX+UNIQ+NOT NULL의 조합.
테이블당 1개 등록 가능.
추가적 할당이 필요하면 위에 3개를 각각 등록 
-----------UNIQ-----------------------------------------------
해당 [컬럼] 혹은 [컬럼 묶음]은  동일한 조합의 ROW값이 들어올 수 없다.

-----------FOREIGN KEY-----------
해당 테이블 컬럼이 다른 테이블 컬럼과 FOREIGN KEY가 등록되면 해당 테이블에 등록된 데이터중에서만 입력 가능.
참조하는 컬럼(자식컬럼?)이 삭제되지 않으면 해당 컬럼 변경 불가.(아니면 FOREIGN KEY 해제필요)

================[VIEW]================
자주 사용하는 SELECT문을 등록하여 테이블처럼 재활용함. 
 - 일반적으로는 VIEW로 DML(INSERT, UPDATE, DELETE) 불가.(단일테이블을 거의 그대로쓰면 가능)

================[캐쉬]================
동일한 SELECT문에 조건값이 동일하면 메모리에 저장된값을 그대로 돌려준다 ( 같은 쿼리 두번 돌렸을때 속도가 다른 이유)

================[SEQUENCE]================
NO, SEQ 등 자동증가 시퀀스값이 필요할 경우 사용
MAX()+1로도 사용 가능하지만 INSERT->SELECT->UPDATE 처럼 한번에 진행하는 경우 제약이 따른다.
단점 : 무조건 순차적으로 발생되야 하는 경우 쿼리 실행 후 오류가 발생하면 중간에 누락값이 생긴다.

-----------생성-----------
CREATE SEQUENCE TEST_SEQ
START WITH 1          -- 시작값
INCREMENT BY 1        -- 증가 단위
NOMAXVALUE;
-----------사용-----------
값을 증가시켜 조회 :  SELECT TEST_SEQ.NEXTVAL FROM DUAL

현재 값으로 조회 :  SELECT TEST_SEQ.CURRVAL FROM DUAL

================[PLSQL]================
PLSQL은 쿼리를 사용할 수 있는 DB문법으로 소스+데이터를 동시에 활용가능한 문법.
 - 보통 SQL툴에서 함수,프로시저,트리거를 따로 볼 수 있음.

-----------------------------------------------
FUNCTION : SQL문에서 활용할 수 있는 함수를 생성.
 - 공통코드 찾는 함수나 자주 사용하는 것들을 함수로 등록하며 활용도가 매우 높음.

-----------------------------------------------
PROCEDURE : 프로시저 함수를 생성해서 그 하나로 여러 분기를 태워 여러 작업을 일괄적으로 실행.
 - 복잡한 업무 진행을 JAVA나 서비스를 이용하지 않고 프로시저로 등록하여 호출(사용 빈도 낮음)

-----------------------------------------------
TRIGGER : 특정 테이블에 DML(INSERT, UPDATE, DELETE) 작업들이 발생 시 자동적으로 다른 작업을 실행.
 - 쿼리나 소스에서 전혀 표기되지 않아서 따로 찾아보지 않으면 알 수 없다는 단점이 있음.(거의 사용안함)
